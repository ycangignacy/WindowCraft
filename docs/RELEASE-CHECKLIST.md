# Release Checklist

Status as of 2026-11-13: 1.4.1 is prepared and not published yet. It fixes the option lists in
the translated languages and seven bugs from a code review of 1.4.0, and moves the credit to
WindowCraft Dev Team, see `docs/RELEASE-NOTES-1.4.1.md`. A short VM pass (upgrade, uninstall, WCLANGUAGE, the fixes in Polish) passed 76 of 76. 1.4.0 is
the current stable release, published with x64 and ARM64 files matching `SHA256SUMS.txt`. It
translates the catalog into the seven other interface languages and closes the rest of the
1.3.0 audit (E10, E11, D1 to D12, offline t14), see `docs/RELEASE-NOTES-1.4.0.md`. 1.3.1
fixed what a full audit of 1.3.0 found in the engine, ISO Studio, the interface, profiles and
translations, see `docs/RELEASE-NOTES-1.3.1.md`. 1.3.0 was published with x64 and ARM64 files matching
`SHA256SUMS.txt`, and added the introduction on the first start and the page tips, see
`docs/RELEASE-NOTES-1.3.0.md`. 1.2.1 fixed what the full VM test of 1.2.0 found. 1.2.0 added the Extensions page (metadata stripper, file converter, ffmpeg, YouTube downloader),
see `docs/RELEASE-NOTES-1.2.0.md`. 1.0.3 fixed the Control Panel applet buttons, KB-9
and KB-10. 1.0.2 moved drawing to the GPU through wgpu (Direct3D 12) with tiny-skia as the
fallback. 1.0.2-rc1 was a pre-release of the same version on the CPU renderer alone. 0.1.0 and
1.0.0 were pre-releases.

The system-changing features ran for the first time on a live system on 2026-11-04: Windows 11
Home 26H2, build 26300, Polish, in VirtualBox 7.2.22, driven by `crates/windowcraft-app/tests/live_vm.rs`
and a PowerShell script in `target/vm/` (not in the repository). The results are in
`docs/RELEASE-NOTES-1.0.1.md`. Section 4 lists what is still open.

Not checked by hand: the eight interface languages on an English Windows and `setup.exe` in each
language. German, Ukrainian and Polish were captured at 980 by 600 on the development machine.

## 5. Known bugs

### Fixed

| ID | Bug | Resolution |
| :--- | :--- | :--- |
| KB-1 | Closing the window during a job gives no warning. The app exits and the job stops partway. Child tools such as winget or DISM probably run on. | Closing the window during a job asks for confirmation. Quitting anyway cancels the job. |
| KB-2 | The exe is a GUI binary, so cmd and PowerShell do not wait for exit codes. Scripted deployments are affected. | Installers add `windowcraft-cli.exe` next to `windowcraft.exe`. It waits and returns the exit code. The portable build uses `Start-Process -Wait` or `\| Out-Null`. |
| KB-3 | Rolling back a session counted native steps as undone without doing anything. Features recorded no native steps at all. | Features record their native steps. A rollback lists what it could not undo, and the session shows "Partly rolled back". |
| KB-4 | The `AutoRegBackup` task and OpenSSH firewall rule could not be removed from inside the app. | Rolling back `reg-backup` deletes `AutoRegBackup` task. Rolling back OpenSSH Server removes its firewall rule. The firewall rule survives uninstall on purpose. |
| KB-5 | Clearing "ISO Studio work files" while an ISO session was open broke the next build. | 1.0.0: the cleaner skips them while an ISO is open or an image is mounted in `iso\mount`. |
| KB-6 | Any unclassified snapshot database error counted as corruption. | 1.0.0: only `StorageError::Corrupted` and an `InvalidData` header move the file aside. `UpgradeRequired` and other errors leave it and report. |
| KB-7 | Unknown fields on `NativeOp` variants without parameters were accepted. | 1.0.0: `native_ops_carry_no_unknown_fields` round-trips every operation in the catalogs. |
| KB-8 | Enabled DISM features stayed enabled after a rollback. | 1.0.0: feature steps record `was_on` from `DismGetFeatureInfo`, and a rollback disables only those that were off. Sessions from 0.1.0 still roll back partly. |
| SEC-1 | The CTT PowerShell profile came from a moving `main` branch. | 1.0.0: pinned to commit `daa7ba2` with SHA-256. 1.1.0: replaced by a profile built into WindowCraft, so nothing is downloaded. |

| KB-9 | Uninstalling while WindowCraft was open left the window running. | 1.0.3: the uninstaller runs `windowcraft.exe --close-running` as SYSTEM before it removes files. Checked in the VM for the MSI and `setup.exe`. |

## 6. Known limitations

These are intended for the release notes.

- WindowCraft runs on Windows 11 only, on x64 and ARM64. The interface is in eight languages;
  catalog content, error details, the job log and command line output are in English.
- The builds are not code-signed, so SmartScreen shows a warning on first run.
- Uninstalling deletes Time Machine history for every user, with no warning. Roll changes back
  first if you want them undone.
- Uninstalling does not undo settings you changed. That covers tweaks, removed apps, installed
  packages including Chocolatey, OpenSSH Server with its firewall rule, restore points and
  backups kept beside system files, such as `hosts.bak`.
- The portable build has no uninstaller. Run `windowcraft.exe --purge-data` from an elevated
  terminal, then delete the file.
  Without elevation it removes only your own data folder.
- The portable build does not contain `windowcraft-cli.exe`. In PowerShell, run
  `Start-Process -Wait .\windowcraft.exe -ArgumentList "..."` or pipe to `Out-Null` to wait for completion.
- Time Machine cannot restore removed packages, uninstalled apps or BitLocker decryption.
- Rolling back OpenSSH Server removes its firewall rule, while the server and its services stay
  installed. The firewall rule survives uninstall on purpose.
- If you elevate with a different administrator account, per-user tweaks go to that account, and
  it has its own separate Time Machine history.
- Commands that use Time Machine, such as `--run` and `--check-drift`, fail while the app is open,
  because only one process can hold the snapshot database.
- `oscdimg` is installed through WinGet during an ISO build and removed afterwards, so the first
  step of every build needs a network connection unless it is already installed.
- The DNS benchmark needs HTTP/2, because Quad9's DoH endpoint does not answer over HTTP/1.1.

## 9. Release steps

1. Set `version` in `Cargo.toml`, write `docs/RELEASE-NOTES-<version>.md`, date the
   `CHANGELOG.md` entry and push `main`.
2. Confirm CI passes.
3. Push tag `v<version>`. `release.yml` builds everything and publishes a pre-release with the
   notes from `docs/RELEASE-NOTES-<version>.md`.
4. Download the files on a clean machine, check `SHA256SUMS.txt`, install and uninstall.
5. Finish section 4 in a VM, and fix what it finds before any stable release.

To make a pre-release stable without changes, edit its GitHub release: clear "Set as a
pre-release", set it as the latest release and drop the suffix from the title. Do not rebuild the
same version under a new tag. The MSI replaces a build of the same version
(`AllowSameVersionUpgrades`), but the WiX 3 bootstrapper does not: in the VM a second
`setup.exe` build of 1.0.2 over the first left two "WindowCraft 1.0.2" entries in Installed apps,
one of them a stale bundle. A stable release with code changes gets the next version number.
